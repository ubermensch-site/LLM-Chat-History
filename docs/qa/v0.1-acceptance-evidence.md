Status: Release-candidate evidence; not final release approval

## Additional roadmap release gates

### Long existing conversations

**BLOCKED / RESCOPE REQUIRED** for guaranteed first-time complete historical import.

The recorder safely reconciles overlapping virtualized rendered windows and retains already captured older turns. A stress test covers >1,000 turns. However, an explicit historical scroll-and-harvest/import workflow for already-long threads is still required by issue #3 and has not been implemented/validated.

### Selector/DOM failure visibility

**PASS (automated), LIVE REQUIRED for current provider structure.**

Repeated empty semantic snapshots escalate from degraded to `selector-failure-suspected` after hysteresis; recorder health code/detail is visible; a privacy-safe diagnostics report is available. Live selector evidence still belongs to issue #3.

### Release package/security boundary

**PASS (automated) on current RC commits.**

CI verifies:

- manifest/package version consistency;
- no production source maps;
- exact minimal permissions and ChatGPT hosts;
- explicit extension CSP;
- no web-accessible/external-connectable surface;
- no remote/inline script or inline event handlers;
- no eval/new-Function/dynamic HTML injection sinks;
- no v0.1 network APIs;
- deterministic ZIP integrity/checksum.

## Required manual/live evidence before release approval

Use `docs/qa/live-chatgpt-validation.md` and record the exact tested commit/artifact/browser/OS. At minimum scenarios 1–8 and 10 must pass. Scenario 9 continuous virtualization behavior must pass; the separate first-time historical-harvest requirement must be implemented or explicitly re-scoped before TASK-054 can close.
